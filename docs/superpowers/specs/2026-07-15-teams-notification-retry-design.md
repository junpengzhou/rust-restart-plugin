# Teams 通知网络重试设计

## 目标

Teams webhook 发送发生网络连接错误时，在等待 1 秒后重试一次。首次发送包含在次数内，因此每个 webhook 最多尝试 2 次。

## 设计

保持 `send_notifications` 的公开接口和现有 webhook 遍历不变。在每个 webhook 内使用一个固定两次的内联循环发送请求：

- 任意一次发送成功后打印成功信息，并立即结束当前 webhook 的循环。
- 第 1 次发生 `reqwest::Error` 时不打印警告，静默等待 1 秒，再进行第 2 次发送。
- 第 2 次仍发生 `reqwest::Error` 时只打印最终失败警告，不再重试，并继续下一个 webhook。
- HTTP 4xx 或 5xx 仍表示已经收到 HTTP 响应，不属于网络连接错误，不触发重试。

实现仅增加最大尝试次数、等待时长常量和内联循环；不新增依赖，不抽取通用重试框架。

## 错误处理

保留现有容错语义：单个 webhook 两次网络发送均失败时，`send_notifications` 仍继续处理其他 webhook，并最终返回 `Ok(())`，避免通知故障中断更新主流程。客户端构造或 payload 构造错误仍通过现有 `AppResult` 返回。

## 测试

按照仓库约定，扩展现有 `tests/teams.rs`：

- 本地 TCP 测试服务让第 1 次连接失败、第 2 次返回成功，验证总连接次数为 2。
- 本地服务返回 HTTP 错误响应，验证只发送 1 次。
- 本地服务连续制造两次网络错误，验证总连接次数止于 2。
- 先运行新增测试确认其因缺少重试而失败，再实现最小代码使其通过。
- 最后运行格式检查、Clippy 和完整 `cargo test`。
